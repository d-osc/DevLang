# DevLang v0.5.6

This release ships **dcc**, a C compiler written in a single DevLang file (`tools/dcc/main.dev`) that can replace clang/GCC as the `devc` backend:

```
d build program.dev --cc tools/dcc/dcc-cc.cmd --output program.exe
```

dcc runs on the DevLang runtime and turns devc-generated C straight into a Windows x86-64 PE executable — its own lexer, C preprocessor, parser, x64 code generator and PE writer, with no C toolchain anywhere in the path. It speaks the cc protocol devc expects (`--version`, `-c` compile, link), so devc's build cache, `--release` and multi-module programs all work unchanged.

What the backend covers today: integer/string/bool programs including functions and recursion, control flow, bitwise and shift operators, the checked runtime helpers (checked division/remainder/shift with located failures on stderr), up to 8 arguments per call, and full float *arithmetic* (exact literals with round-half-even, `+ - * /`, comparisons with C NaN semantics, int<->double casts, f64 parameters and returns via SSE2). Functions are emitted only when reachable from `main`, so unused devc prelude code is dropped automatically.

Known limits, all reported as clear build errors: printing `%f/%g` values (msvcrt `printf` with doubles does not behave under x64 emulation on ARM64 machines — cast to int or use the clang/GCC backend for float-heavy output), struct/record values, dynamic values and heap allocation, and `--lib` archives. See `tools/dcc/README.md` for the full contract and debugging tips (`dccdbg`).

Assets include Windows/Linux x86_64 and ARM64 binaries and offline installers. The Windows single-file GUI installer is x86_64. Native compilation still also works with Clang/GCC or bundled TinyCC. Installers are unsigned.
